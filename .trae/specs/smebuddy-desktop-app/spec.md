# SMEbuddy 风格 AI 智能体桌面工作台 - 产品需求文档

## Overview

- **Summary**：开发一个类似腾讯 SMEbuddy 的**独立桌面客户端**（Windows 优先）。用户用一句话下达任务，AI Agent 自主规划、调用工具（联网搜索/文件生成）、流式展示执行过程，并交付 Markdown / Word / PPT 等可验收产物。应用包含对话式任务台、专家 Agent 广场、深度调研与产物管理、模型与技能管理四大模块。
- **Purpose**：在本地拥有一个「一人指挥、专家团执行」的 AI 办公工作台，数据与凭证留在本机，无需登录云端账号即可使用自带的 OpenAI 兼容模型服务。
- **Target Users**：个体创业者、自由职业者、知识工作者、运营/数据/开发/设计等需要 AI 完成调研、文档、PPT、分析任务的职场用户。

## Goals

- 还原 SMEbuddy 的核心产品范式：**一句话任务 → 自主规划 → 多步执行（含联网搜索）→ 产物交付**。
- 三栏桌面工作台布局（任务侧边栏 / 对话区 / 结果区），交互与视觉对标 SMEbuddy。
- 专家 Agent 广场：内置覆盖运营、设计、数据、开发、写作、商务等角色的专家团，并支持自定义专家。
- 深度调研：Agent 自动拆解搜索路径、联网检索、交叉汇总，输出结构化报告。
- 产物体系：Markdown / Word(.docx) / PPT(.pptx) 生成、预览、打开与另存。
- 模型与技能可配置：任意 OpenAI 兼容接口（OpenAI / DeepSeek / 本地 Ollama 等）、模型切换、本地用量统计、技能开关与自定义技能。
- 完整的桌面分发链路：开发模式一键启动，生产模式产出可安装的 Windows x64 安装包（不依赖用户机器预装 Python）。

## Non-Goals

- IM 远程助理（微信/企业微信/QQ/钉钉/飞书机器人远程控制）。
- 云账号、登录注册、多端云同步、订阅支付与真实积分扣费（仅做本地用量计量）。
- 移动端 App / 小程序。
- 真实第三方办公系统对接（Jira / Notion / Slack 等连接器仅做「即将推出」占位）。
- 代码执行沙箱与在用户机器上运行不受信任代码的能力。
- macOS / Linux 打包（架构预留，本期仅产出 Windows x64 产物）。
- 语音/图片多模态输入（本期仅文本与文件附件中的文本类数据）。

## Background & Context

- 参考产品：腾讯 SMEbuddy（smebuddy.tencent.com / smebuddy.ai），官方定位「全场景职场 AI 智能体桌面工作台」。
- 官方公开信息确认的关键形态：
  - 桌面端三区结构：**侧边栏**（任务列表按文件夹分组、搜索、底部用户区）、**对话区**（任务标题栏、消息列表、输入框）、**结果区**（产物 / 全部文件 / 预览视图）。
  - 执行流：接收指令 → 输出规划 → 并行/串行调用工具（如搜索 20 份报告）→ 生成 `.md` / `.docx` / `.pptx` 等 Artifacts → 过程与结果均可回看。
  - 100+ 领域专家、多模型路由、Skills & Connectors 扩展、积分额度体系。
- 用户已确认的决策：
  1. 应用形态 = **桌面客户端**；
  2. MVP 范围 = 对话式任务台 + 专家 Agent 广场 + 深度调研+产物 + 模型与技能管理（全部四项）；
  3. 模型接入 = **OpenAI 兼容接口**（base_url + api_key 可配置）。

## Functional Requirements

### A. 桌面壳与应用框架

- **FR-1**：Electron 桌面应用，主进程负责窗口管理与本地后端 sidecar 的生命周期：启动时拉起后端、健康检查通过后再加载界面；应用退出时确保子进程被终止。
- **FR-2**：主界面为三栏工作台布局，可调整左右栏宽度；窗口尺寸、栏宽等偏好本地记忆。
- **FR-3**：所有业务数据（任务、消息、专家、技能、产物索引、设置、用量）本地持久化，应用与机器重启后不丢失。
- **FR-4**：提供开发模式一键启动（Vite 热更新前端 + 本地 FastAPI），以及生产构建链路（PyInstaller 打包后端为 exe → electron-builder 封装安装包）。

### B. 对话式任务台

- **FR-5**：可新建任务；侧边栏按文件夹分组展示任务列表，支持任务重命名、删除、关键词搜索；支持新建文件夹与任务移动（移动至少支持在任务上通过菜单选择文件夹）。
- **FR-6**：对话区支持多轮对话；输入框多行输入、Enter 发送 / Shift+Enter 换行；执行中显示「停止生成」按钮。
- **FR-7**：后端以 SSE 流式推送 Agent 事件，前端按事件类型实时渲染：思考（think）、规划步骤（plan）、工具调用（tool_call：搜索/抓取/写文件，含状态与来源）、正文消息（message delta）、产物登记（artifact）、完成/错误（done/error）。
- **FR-8**：任务执行可被用户中断；中断后停止后端推理、UI 回到可输入状态，已产生的过程与文件保留，用户可继续追问。
- **FR-9**：Agent Loop：系统提示词（专家+技能）+ 历史上下文 + 可用工具 schema 发送给模型；模型决定工具调用，后端执行工具并回灌结果，循环至产出最终答复；单任务有最大轮次与超时保护。
- **FR-10**：异常场景有明确可恢复的提示：未配置模型 / API Key 无效、网络不可达、模型返回错误、超时、中断。

### C. 专家 Agent 广场

- **FR-11**：独立「专家广场」页面：卡片网格展示专家（彩色头像、名称、角色一句话描述、分类标签），支持分类筛选与关键词搜索。
- **FR-12**：内置不少于 12 个预置专家，至少覆盖：产品经理、软件工程师、测试 QA、UI/UX 设计师、运营专家、市场/营销、数据分析师、财务、法务、文案写作、行业研究员、PPT/汇报专家；每个专家含名称、头像标识、分类、详细描述、系统提示词、2~3 个推荐开场问题。
- **FR-13**：点击专家卡片打开详情，可查看其能力说明与推荐问题，点击「开始任务」即以该专家身份创建任务会话（请求携带该专家系统提示词）。
- **FR-14**：支持创建、编辑、删除自定义专家（名称、emoji 头像、分类、描述、系统提示词）；自定义专家与内置专家在广场同样可见，内置专家不可删除但可复制后自定义。

### D. 深度调研与产物

- **FR-15**：「深度调研」作为内置技能/工具编排：Agent 自动拆解多个搜索子问题 → 逐个联网搜索 → 选择性抓取网页正文 → 去重交叉验证 → 汇总成文。
- **FR-16**：工具调用过程在消息流中以可折叠卡片呈现（搜索词、结果条数、来源标题与 URL、抓取状态、耗时），最终报告以脚注或「参考来源」列表列出引用链接。
- **FR-17**：支持产物格式 Markdown（.md）、Word（.docx，含标题层级与基本排版）、PPT（.pptx，标题页+目录+内容页的模板化排版）；由 Agent 根据任务意图自动选择，或按用户明确指令产出指定格式，一次任务可产出多个文件。
- **FR-18**：右侧结果区提供「产物」与「全部文件」视图：文件图标、名称、格式、大小、生成时间；操作包括应用内预览（.md/.txt）、用系统默认程序打开、打开所在目录、另存为。
- **FR-19**：每个任务拥有独立工作目录（`artifacts/<task_id>/`），后端登记产物元数据；删除任务时其文件进入可恢复策略（默认一并删除但需二次确认）。
- **FR-20**：在无专业搜索 API Key 时使用免 Key 搜索源（DuckDuckGo）可用；设置页允许配置可选的 Tavily 等搜索 API 以提升质量。

### E. 模型与技能管理

- **FR-21**：设置页可管理 OpenAI 兼容连接：显示名称、Base URL、API Key（密文存储、界面掩码）、模型 ID 列表（可添加多个模型、删改）、超时；提供「测试连接」（发起一次最小 chat 请求）。
- **FR-22**：对话区可切换当前任务使用的模型（来自已配置列表）；切换后下一条请求即生效；首次启动且无任何可用模型配置时，首页给出引导卡片跳转设置。
- **FR-23**：本地用量统计：按任务/总计记录请求次数、输入/输出 token（以接口 usage 字段为准，无 usage 时估算），在设置或任务信息中展示；不涉及真实扣费。
- **FR-24**：技能（Skills）管理页：列出内置技能（深度调研、文档生成、PPT 生成）并可启用/停用；支持新建自定义技能（名称、描述/触发说明、提示词模板）；发起任务前可在输入区选择挂载的技能，挂载后其提示词注入 Agent 上下文。
- **FR-25**：设置中提供「连接器」展示区（Jira、Notion、Slack、Google Drive 等生态标识），统一标注「即将推出」，不提供真实配置入口。

## Non-Functional Requirements

- **NFR-1（响应体验）**：后端就绪后，发送消息到首个 SSE 事件在正常网络下 ≤ 3 秒；流式内容在到达后 ≤ 200ms 渲染；长任务（调研）全程界面不卡死、可滚动。
- **NFR-2（平台与启动）**：Windows 10/11 x64 运行；开发环境冷启动到界面可交互 ≤ 10 秒；生产安装包双击安装后无需用户自行安装 Python/Node。
- **NFR-3（安全与隐私）**：API Key 仅保存在本机（SQLite 中加密存储或受 OS 用户目录保护）；除用户配置的模型接口与搜索源外，应用不向任何第三方上报数据。
- **NFR-4（视觉质量）**：中文界面，现代简洁的工作台风格（浅色为主、圆角卡片、克制的品牌色、专家彩色头像），布局与交互对标 SMEbuddy 公开版本。
- **NFR-5（可运维性）**：后端提供结构化日志与日志文件；前端请求错误有统一提示；sidecar 异常退出时主进程提示并可重启。
- **NFR-6（工程质量）**：前后端分离、清晰的目录分层；接口契约集中定义（Pydantic 模型 + TS 类型/DTO）；无显式 any 兜底的关键链路；核心后端逻辑（Agent 事件、工具、产物生成）具备可在无 LLM 条件下运行的单元测试（mock 模型）。

## Constraints

- **Technical**：
  - 壳：Electron（最新稳定线，≥ 30）+ electron-builder（Windows NSIS x64）。
  - 前端：React 18 + TypeScript + Vite + Ant Design 5 + Zustand + React Router（遵循用户既定技术栈）。
  - 后端：Python 3.11+ / FastAPI / SQLAlchemy 2.0 / Pydantic v2；以 **PyInstaller** 单文件 exe 形式作为 sidecar 被 Electron 管理。
  - 本地数据库：**SQLite（WAL 模式）**——桌面单机应用，替代用户常用栈中的 PostgreSQL/Redis。
  - Agent：官方 `openai` Python SDK（OpenAI 兼容 chat.completions + 流式）；SSE 采用 SSE 风格流式（`text/event-stream`）。
  - 搜索：免 Key 默认 DuckDuckGo（`duckduckgo_search` 等），可选 Tavily；网页抓取：httpx + trafilatura/readability 类正文提取。
  - 产物：Markdown 原生；`python-docx`；`python-pptx`。
- **Business**：单用户本地软件；无付费；API 调用费用与额度由用户自行向其模型服务商承担。
- **Dependencies**：Node 18+、Python 3.11+（仅开发/构建机需要）；产物运行机仅需 Windows 10+ x64；联网；用户自备 OpenAI 兼容 API 凭证。

## Assumptions

- 以 SMEbuddy 公开官网、官方文档描述的三栏布局与交互作为「1:1 复刻」依据；登录后内部页面无法公开获取的细节（精确色值、图标）以官方描述 + 现代工作台通用范式还原，并在实现阶段就关键界面征求确认。
- 桌面端为本地单用户，故不引入登录体系、PostgreSQL、Redis；如未来需要云同步再演进。
- 用户能自行提供至少一个 OpenAI 兼容服务的 Base URL 与 API Key；没有凭证时应用可启动、可浏览界面，但任务执行会被引导至设置页。
- PPT 产物采用内置模板化排版（封面/目录/章节内容/结尾），不追求像素级设计排版。
- 深度调研的搜索质量受免费搜索源限制，配置 Tavily 等可获得更好结果。

## Acceptance Criteria

### AC-1：开发环境可一键启动完整应用
- **Type**: `rule`
- **Given**: 全新克隆的仓库，已安装 Node 18+ 与 Python 3.11+ 并完成依赖安装
- **When**: 执行开发启动命令
- **Then**: Electron 窗口出现并加载三栏工作台，FastAPI sidecar 健康检查通过
- **Pass Condition**: `npm run dev` 一条命令后 10 秒内窗口可交互；访问后端 `/healthz` 返回 200
- **Evidence**: 启动命令输出与窗口截图、`/healthz` 响应

### AC-2：未配置模型时的拦截与配置闭环
- **Type**: `rule`
- **Given**: 全新本地数据（无任何模型配置）
- **When**: 用户打开发送任意任务消息
- **Then**: 请求被前端拦截并出现引导，进入设置填写 Base URL / API Key / 模型并测试连接成功后，返回对话可正常发送
- **Pass Condition**: 未配置时无法发起任务且有明确引导；测试连接成功后配置持久化，重开应用仍在
- **Evidence**: 界面截图；设置接口请求/响应；重启后配置仍存在的验证

### AC-3：Agent 执行过程真实流式渲染
- **Type**: `rule`
- **Given**: 已配置可用的 OpenAI 兼容模型
- **When**: 用户发送一个需要规划与工具的任务（如「调研 X 并生成报告」）
- **Then**: 对话流中按时间顺序实时出现规划步骤、工具调用卡片（含搜索词/来源 URL）、正文增量内容、产物卡片，而非等待整段完成
- **Pass Condition**: 抓包/日志确认 SSE 事件分帧推送；界面上首个事件在最终完成前已渲染；事件类型至少包含 plan、tool_call、message、artifact
- **Evidence**: SSE 事件日志（脱敏）；执行过程录屏或连续截图

### AC-4：任务可中断且状态一致
- **Type**: `rule`
- **Given**: 一个正在执行的任务
- **When**: 用户点击「停止生成」
- **Then**: 后端流被取消、不再产生工具调用与计费请求，输入框恢复可用，已生成内容与产物保留，可继续追问
- **Pass Condition**: 中断后 1 秒内 UI 恢复；后端日志无中断后的继续调用；刷新后内容仍在
- **Evidence**: 操作录屏；后端日志

### AC-5：数据持久化
- **Type**: `rule`
- **Given**: 用户已创建任务、消息、自定义专家、自定义技能并修改设置
- **When**: 完全退出并重新启动应用
- **Then**: 全部数据原样存在（任务列表、消息与过程块、产物记录、设置、专家与技能）
- **Pass Condition**: 重启后以上数据逐一可见；产物文件仍可打开
- **Evidence**: 重启前后对比截图

### AC-6：专家广场与专家初始化会话
- **Type**: `rule`
- **Given**: 内置专家数据
- **When**: 打开专家广场，按分类筛选、关键词搜索，并从某专家「开始任务」
- **Then**: 展示 ≥12 个内置专家；筛选/搜索结果正确；新任务请求体包含该专家的系统提示词
- **Pass Condition**: 专家数量与分类正确；后端接收到的首个请求 messages 中含专家 system prompt；可成功创建自定义专家并出现在广场
- **Evidence**: 广场截图；后端请求日志；自定义专家创建记录

### AC-7：深度调研真实联网并产出报告
- **Type**: `rule`
- **Given**: 挂载/命中深度调研技能
- **When**: 发起「深度调研某主题，输出报告」任务
- **Then**: 至少发生 1 次真实联网搜索（默认 DuckDuckGo），工具卡片展示来源 URL，任务目录产出 Markdown 报告，报告含参考来源列表
- **Pass Condition**: 后端日志出现真实搜索请求与 ≥3 条结果；`.md` 文件存在且含标题结构与来源 URL
- **Evidence**: 工具事件日志；产出的 .md 文件内容

### AC-8：Word 与 PPT 产物有效可用
- **Type**: `rule`
- **Given**: 用户明确要求生成 Word/PPT
- **When**: 任务完成
- **Then**: `artifacts/<task_id>/` 下生成有效 `.docx` / `.pptx`，可被 Office/WPS 正常打开，PPT 至少含标题页与内容页
- **Pass Condition**: 文件存在、扩展名正确、OOXML 文件头与结构校验通过（python-docx/python-pptx 可重新读取且页数/段落数 >0）
- **Evidence**: 文件校验脚本输出；Office 打开截图

### AC-9：结果区文件操作闭环
- **Type**: `rule`
- **Given**: 任务已产出若干文件
- **When**: 在结果区对产物执行预览/打开/打开目录/另存为
- **Then**: `.md` 应用内预览正常；「打开」调用系统默认程序；「打开目录」定位到文件；「另存为」复制到用户选择路径
- **Pass Condition**: 四类操作各成功一次（可通过 IPC 调用参数与文件系统结果验证）
- **Evidence**: 操作演示；IPC 日志与目标路径文件存在性

### AC-10：技能与模型管理生效
- **Type**: `rule`
- **Given**: 已配置 ≥2 个模型、已创建自定义技能
- **When**: 切换模型并挂载自定义技能后发起任务
- **Then**: 后端请求体的 model 为所选模型；system/上下文消息包含自定义技能提示词；内置技能可停用且停用时不再注入对应工具/提示
- **Pass Condition**: 后端日志同时验证 model 字段与技能注入内容；停用深度调研后普通任务不出现搜索工具
- **Evidence**: 后端日志/请求记录

### AC-11：生产安装包无外部运行时依赖
- **Type**: `rule`
- **Given**: 构建机完成打包
- **When**: 在未安装 Python 的干净 Windows 10/11 x64 环境（或干净用户目录）安装并启动
- **Then**: 应用正常启动、sidecar 就绪、可走到模型配置页并发起请求
- **Pass Condition**: electron-builder 产出 NSIS 安装包；安装目录内含后端 exe；启动时任务管理器可见 sidecar 进程随应用退出而结束
- **Evidence**: 构建产物路径与文件清单；干净环境启动截图/进程列表

### AC-12：异常可观测与可恢复
- **Type**: `rule`
- **Given**: 配置了错误的 API Key 或断网
- **When**: 发起任务
- **Then**: 对话中出现明确错误条（原因可读），输入框保持可用，修正配置后可重试成功；日志文件记录错误堆栈
- **Pass Condition**: 三类错误（401/网络/超时）各有对应提示且不白屏、不丢输入内容
- **Evidence**: 错误场景截图；日志文件片段

### AC-U1：SMEbuddy 视觉与布局还原度

### AC-U2：Agent 过程的可读性与质感
